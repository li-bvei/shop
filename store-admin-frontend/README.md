# store-admin-frontend

Vue 3 (`<script setup>`) + TypeScript + Vite frontend for 店铺管理系统, talking
to the real Django backend in `../store-admin-backend` (no mock layer —
`src/mock/` was fully removed once the backend migration finished).

## Stack

- Vue 3.5 + TypeScript + Vite
- Element Plus 2.14 (UI components)
- Pinia (`stores/auth`, `stores/preference`, `stores/branches`)
- vue-i18n 9 — full 中文/日本語 coverage, no hardcoded business text in components
- ECharts (via `vue-echarts`) for the dashboard and monthly-analysis charts
- Browser-native `window.print()` + `@media print` for every PDF-style export
  (daily report, wage payslip, monthly summary) — no Excel or PDF-generation library

## Setup

```bash
npm install
npm run dev
```

Point it at a running backend (see `../store-admin-backend/README.md`). Local
development uses `.env.development.local`; production must provide
`VITE_API_BASE_URL` from the deployment environment (see
`.env.production.example`). `.env.local` intentionally contains no API URL
because Vite loads it during production builds too.

## Architecture conventions

- **`src/api/*.ts` is the only data layer.** Vue components never call
  `fetch`/`http` directly. Each file owns one backend app's DTO conversion
  (snake_case ↔ camelCase) and stringifies numeric backend primary keys
  (`String(id)`) so the rest of the app can keep treating ids as strings —
  `PaymentMethodDef.id` is a deliberate exception (stays `number`) because it
  never flows into a `v-model` or route param, only a function argument.
- **`src/api/http.ts`** wraps `fetch`: attaches `Authorization: Bearer`,
  silently retries once via refresh token on a 401, and `ApiError.messages()`
  flattens DRF's two error shapes (`["msg"]` vs `{field: ["msg"]}"`) into one
  consistent array every form can render.
- **Session restore ordering**: `main.ts` must `await` both
  `authStore.restoreSession()` and `preferenceStore.init()` **before**
  `app.use(router)` — Vue Router 4's first navigation guard fires at
  `app.use(router)`, not `app.mount()`. Getting this order wrong bounces an
  already-logged-in user back to `/login` on every page refresh.
- **Role-based routing**: `router/index.ts` gates every route via
  `meta.roles: ('admin' | 'branch' | 'staff')[]`, checked in `beforeEach`.
  This mirrors the backend's permission checks for UX only — it is never a
  substitute for them; every endpoint is independently enforced server-side
  (see `../store-admin-backend/README.md`'s permission matrix).
- **Money math never happens in the frontend.** Every yen amount rendered
  anywhere (daily report, wages, monthly analysis) is a number returned
  directly by the API; the frontend only formats it (`utils/format.ts:formatCurrency`).
- **JST-aware dates**: `utils/format.ts:todayJst()`/`currentMonthJst()` use
  the `Intl.DateTimeFormat('sv-SE', {timeZone:'Asia/Tokyo'})` trick to derive
  "today" in Japan time regardless of the browser's own timezone — used
  everywhere a form defaults to "today" or "this month".
- **Print targets** follow one pattern throughout: a hidden `#print-area` div
  styled only under `@media print`, `document.title` swapped immediately
  before `window.print()` to suggest a filename, then restored. A page that
  forgets the `id="print-area"` wrapper prints entirely blank — the global
  rule in `assets/styles/global.css` hides `body *` by default and only
  un-hides that one element.
- **Deleting an `ActualWorkRecord`**: `SchedulingView.vue`'s delete action is
  not a plain `DELETE` call. A record still linked to a `Shift` gets silently
  regenerated by the backend's `generate_actual_records` on the next draft
  save (it's `get_or_create`, keyed on employee+date, and only fills gaps),
  so deleting it would reappear. The frontend checks `plannedStart === null`
  first: linked records are `PATCH`ed to `absent: true` instead (stable, and
  already excluded from wage calculation server-side); only unlinked ad-hoc
  records get a real `DELETE`.
- No `vite-plugin-vue-devtools` — it was removed (it only ever affected the
  dev server, injecting a floating devtools icon into every page; never
  shipped in production builds).

## Pages

| route | roles | notes |
| --- | --- | --- |
| `/dashboard` | admin, branch | today/yesterday KPIs, 14-day trend, branch comparison |
| `/monthly-analysis` | admin, branch | month picker, KPI deltas, trend/payment/weekday/supplier/branch-comparison charts, deterministic insights, printable summary |
| `/daily-report` | admin, branch | daily entry + payment/expense detail + edit history + PDF export |
| `/purchasing` | admin, branch | Excel-style single-row entry with item/price autocomplete; server-side filter (month/date-range/branch/supplier/item name/price-change), price-history drawer, cross-supplier comparison |
| `/suppliers` | admin, branch | supplier CRUD (incl. remittance account + kana reading of the account holder's name) + payable tracking + PDF export |
| `/staff` | admin, branch | employee roster CRUD, branch-scoped; admin-only inter-branch transfer with audit history |
| `/scheduling` | admin, branch | month-only flow; hall table above kitchen table, date rows × employee columns; left-click cycles a cell forward (休→上午→下午→全日), right-click cycles it backward so any state is a single click away; partial-save preservation; publish + actual-work confirmation, where the delete action either hard-deletes an unlinked ad-hoc record or marks a shift-linked one absent (see backend README's scheduling section for why) |
| `/wages` | admin, branch | simple monthly table: confirmed actual hours × hourly rate + inline transportation + bonus; no user-visible wage-rule/month-closing creation |
| `/promotions` | admin, branch | loyalty-card campaign admin (`promotions` app): campaigns / customers / check-in + draw records / risk flags / monthly report tabs; prize-pool drawer + milestones (writes admin-only); store-QR generator |
| `/lottery` | admin, branch, staff | standalone lottery-record entry (`lottery` app): 大饼 / 京都愛電王 winner logging + Excel export. **No sidebar item — reach it by URL** |
| `/settings` | admin, branch | branch management, account management (incl. staff account creation), payment method master data with drag-to-reorder |
| `/my-availability` | staff | submit availability wishes for an open schedule period |
| `/my-shifts` | staff | read-only view of own published shifts |
| `/my-wages` | staff | own wage results + printable personal payslip |
| `/my-password` | staff | self password change |

### Full-screen kiosk (outside `AppShell` — no admin chrome)

| route | roles | notes |
| --- | --- | --- |
| `/kiosk/verify` | staff, branch, admin | counter tablet: scan a customer card → confirm the spend amount → grant points / advance the stamp card. The one trusted event in the loyalty feature |
| `/kiosk/redeem` | staff, branch, admin | counter tablet: enter a redemption code → mark a next-visit voucher used (approval-required prizes need branch/admin) |

### Public loyalty card (`/pc/*`, no auth, `GuestShell`, JA-first)

| route | notes |
| --- | --- |
| `/pc/register?t=<store_token>` | open a card — the landing page for the printed store QR. `store_token` comes from `CampaignSerializer.store_token` / `seed_promotions_demo`. Optional 6-digit recovery PIN |
| `/pc/card` | the customer's own card — points, ledger, active vouchers, milestones, spend-points actions. Needs the `pc_guest` cookie or `X-Guest-Token` |
| `/pc/login` | new-device recovery — **暗証番号** tab (phone + PIN → full card) or **誕生日** tab (phone + birthday → read-only snapshot, never returns the token) |

## Current wage workflow (3 steps)

1. Set hourly rate/default monthly transportation/effective date in Staff.
2. Select branch and month on Wages, then click Calculate/Update.
3. Enter monthly transportation/bonus (bonus needs a note), then Confirm.

Regular-monthly employees are retained in Staff but are not calculated by
v2_simple. Advanced calculation dates are available in the row expansion and
immediately trigger a server-side recalculation.
